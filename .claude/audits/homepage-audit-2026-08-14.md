### [P1] Testimonials: автоплей нельзя остановить с клавиатуры/тача — ✅ СДЕЛАНО

- **Коммит:** `ff18d6d fix(testimonials): add a manual pause control for the autoplay carousel`
- **Что сделано:** кнопка паузы/воспроизведения рядом с полосой прогресса, по образцу `Carousel.jsx`. Заодно поправлен эффект `isInView` — раньше он безусловно вызывал `autoplay.start()` при возврате секции в кадр и мог тихо сбросить ручную паузу; теперь оба условия (видимость + `isPlaying`) объединены в одном эффекте.
- **Проверено:** клик/Enter останавливают автоплей (слайд не сменился за 6с при задержке 5с), Tab доходит до кнопки, кольцо фокуса `--color-blue-700` (не `--color-blue-300` — см. P2 ниже, не стал тащить непроверенный контраст в новый код), кнопка не перекрывает карточку (`top: 100%` вместо `bottom: 0`), мобильный вьюпорт без горизонтального скролла.
- **Категория:** Accessibility
- **Локация:** `src/sections/testimonials/Testimonials.jsx`
- **WCAG:** 2.2.2 Pause, Stop, Hide (Level A)
- **Как проверено:** в браузере, DOM-запрос внутри `.testimonials` — **ноль** кнопок.
- **Impact:** `pauseOnMouseEnter: true` останавливает автоплей только для мыши. Клавиатурные и тач-пользователи не могут остановить движение вообще.
- **Контекст:** ровно эту же проблему уже решили в Showcasing — там есть `.carousel__toggle` (`src/components/carousel/Carousel.jsx`) с комментарием «единственный способ для клавиатурных и тач-пользователей остановить движение — требование WCAG 2.2.2». В Testimonials починка не долетела.
- **Рекомендация:** добавить в `Testimonials.jsx` кнопку паузы/воспроизведения по образцу `Carousel.jsx`.
- **Команда:** `/impeccable polish testimonials`

### [P2] Растянутые мобильные/планшетные варианты изображений — ✅ СДЕЛАНО

- **Категория:** Performance
- **Локация:** `build/assets/waterdel-mobile-*.webp`, `mish-tablet-*.webp`, `vam-voda-tablet-*.webp` (источники — `src/sections/projects/projects.js`)
- **Как проверено:** `ls -la build/assets/*.webp`, отсортировано по размеру.
- **Данные:**
  - `waterdel-mobile.webp` — 491 КБ (для сравнения `vam-voda-mobile.webp` — 136 КБ при той же роли)
  - `mish-tablet.webp` — 309 КБ
  - `vam-voda-tablet.webp` — 286 КБ
- **Impact:** все три реально отдаются на главной — Showcasing показывает только `isBest: true` проекты (waterdel и mish входят в их число), то есть это не мёртвый вес, а то, что реально грузит мобильный трафик.

**Что нашлось при разборе (глубже, чем в исходной формулировке).** Дело не в качестве сжатия, а в физических размерах файлов: это не подготовленные под карточку кропы, а цельные скриншоты страниц во всю прокручиваемую высоту, поверх которых `object-fit: cover` вырезает только видимую часть в браузере, но не в сети. Замер (`file`, WebP-заголовок):

| Файл                                                | Было      | Нужно (реальный aspect-ratio карточки) | Превышение |
| --------------------------------------------------- | --------- | -------------------------------------- | ---------- |
| `mish-mobile.webp`                                  | 480×7331  | 480×640 (3:4)                          | **11.5×**  |
| `mish-tablet.webp`                                  | 1536×8403 | 1536×864 (16:9)                        | **9.7×**   |
| `waterdel-mobile.webp`                              | 580×4580  | 580×773 (3:4)                          | **5.9×**   |
| `mish.webp` (десктоп)                               | 1439×3024 | 1439×809 (16:9)                        | 3.7×       |
| `vam-voda-tablet.webp`                              | 938×1667  | 938×528 (16:9)                         | 3.16×      |
| `waterdel-tablet.webp` / `landing-area-tablet.webp` | 938×1235  | 938×528 (16:9)                         | 2.34×      |

Оказалось системнее исходной формулировки: не 3 файла, а фактически все tablet-варианты и большинство mobile у всех 4 `isBest`-проектов.

**Риск, который чуть не сломал `/projects`.** Эти же файлы (`img`/`imgTablet`/`imgMobile`) переиспользуются `ProjectCard` на `/projects` — там `imgHeight` в `projects.js` (например, `mish: 1383`) посчитан именно под натуральное соотношение сторон исходного файла (`658 × 3024/1439 = 1382.7 ≈ 1383`, проверено для трёх проектов). Кроп по месту сломал бы `/projects`. Поэтому кроп сделан в **отдельные файлы** — `*-cover.webp` — и подключён только в `Carousel.jsx`/`ShowcasingCard`; `img`/`imgTablet`/`imgMobile` не тронуты.

- **Как сделано:** `sharp-cli extract` (top-aligned кроп до нужного aspect-ratio — совпадает с уже применяемым в CSS `object-position: top`, то есть визуально ничего не меняется) + пересжатие `-f webp -q 85`. 12 новых файлов (4 проекта × 3 брейкпоинта) в `src/assets/projects/*-cover.webp`.
- **Данные после:** суммарный вес 12 файлов 2.51 МБ → 556 КБ (**-78%**); для мобильных вариантов конкретно 928 КБ → 146 КБ (**-84%**).
- **Проверено:** визуально Showcasing идентичен (кроп = уже показанная часть), `/projects` использует `currentSrc`/`naturalWidth`/`naturalHeight` оригиналов (в т.ч. `mish-BiIrvWrx.webp` 1439×3024 — не тронут), детектор — 0 находок.
- **Не закоммичено.**

### [P2] Кольцо фокуса `--color-blue-300` не проходит контраст 3:1 — ✅ СДЕЛАНО

- **Категория:** Accessibility
- **Локация:** `src/components/socials/style.css` (`.socials__link--blue:focus-visible`), `src/components/Up/style.css` (`.scroll-to:focus-visible`), `src/components/ctaButton/style.css` (`.cta-button--pill:focus-visible`), `src/components/logo/style.css` (`.logo__link:focus-visible`)
- **WCAG:** 1.4.11 Non-text Contrast (AA), порог 3:1
- **Как проверено:** формула контраста WCAG, `#60a5fa` (--color-blue-300) на `#ffffff` = **2.54:1**.
- **Контекст:** это исходный выбор кодовой базы (был в `cta-button--pill`, `Logo` до текущей сессии). В этой же сессии тем же цветом дополнительно починили `.socials__link--blue` и `.scroll-to` (заменяя невидимое белое кольцо на видимое, но недостаточно контрастное) — итого было 4 компонента с одним и тем же пограничным кольцом.
- **Что сделано:** во всех 4 местах `--color-blue-300` → `--color-blue-700` (5.17:1 на белом) — тот же цвет, что уже верно использовался в `ButtonLink`/`toggle-btn`. Все 4 места сидят на светлом фоне (проверено, включая Footer — своего фона не задаёт, наследует белый), поэтому единая замена корректна везде без разбора по месту.
- **Проверено:** computed style `outline` во всех 4 местах — `rgb(37, 99, 235) solid 2px`; скриншот `.socials__link--blue` в фокусе — кольцо читается отдельно от кобальтовой заливки иконки за счёт `outline-offset: 2px`. Детектор — 16 находок, все пре-существующие (font-size/color/radius дрейф из P3), ни одна не касается изменённого правила.
- **Не закоммичено.**

## Паттерны и системные проблемы

- **Кольцо фокуса светлым кобальтом на белом** — не единичная ошибка, а повторяемый (уже 4 раза) выбор цвета ниже порога контраста.
- **Дрейф токенов** — не 2-3 файла, а системная черта почти всех секций главной; DESIGN.md документирует шкалу, которой код не придерживается буквально.

## Положительные находки (сохранить как есть)

- Контраст текста — проверен для `gray-500`/`gray-800`/`blue-700`/`violet-500` на белом: все ≥4.89:1, с запасом выше AA.
- Форма Contact — образцовая: `aria-required`, `aria-invalid`, `aria-describedby` → `role="alert"`, звёздочка обязательности скрыта от AT (`aria-hidden`), чтобы не дублировать объявление.
- Иерархия заголовков — один H1, чистые H2/H3 без пропусков уровней; decorative-иконки соцсетей с пустым `alt` корректно прикрыты `aria-label` на самой ссылке.
- `useAutoplayProgress` пишет прогресс-бар напрямую в CSS-переменную через ref, минуя re-render React — без layout thrashing.
- `will-change` — ровно одно применение (звёздный фон `AnimatedBackground`), не разбросано по проекту.
- Lazy-загрузка секций (Showcasing, Testimonials через `React.lazy`) и картинок (`loading="lazy"`), `<picture>` с WebP+JPEG fallback — уже сделано.
