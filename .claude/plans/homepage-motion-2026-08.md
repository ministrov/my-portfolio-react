## 1. Развилка по инструменту — решена

Есть два разных механизма, которые постоянно путают:

|                      | Что делает                                         | Ощущение            |
| -------------------- | -------------------------------------------------- | ------------------- |
| **Scroll-triggered** | Элемент попал в кадр → проиграть анимацию один раз | «что-то проявилось» |
| **Scroll-linked**    | Позиция анимации **и есть** позиция скролла        | «страница живая»    |

Всё, что было на сайте раньше, — первое. Поэтому оно и ощущалось
шаблоном: анимация не связана с пользователем, она выстреливает по
таймеру. Вторая реагирует непрерывно, в обе стороны, со скоростью
пользователя.

### Граница между системами

Чтобы в проекте не оказалось двух конкурирующих систем движения:

- **CSS scroll-timelines** (`animation-timeline: view()`) — всё
  непрерывное, привязанное к скроллу. Считается вне основного потока,
  ноль JS, ложится в конвенцию проекта «обычный CSS + BEM».
- **`motion`** — остаётся там, где движение дискретное и по действию:
  аккордеон FAQ (`AccordionPanel`), форма↔успех и inline-ошибки
  (`ContactForm`), `AnimatePresence`, `useInView` для гейтов автоплея.

Не смешивать: если приём непрерывный — это CSS; если он про смену
состояния — это `motion`.

## 2. Контракт на всё новое

Версии браузеров в плане намеренно не указаны — поддержка проверяется
конструкцией, а не таблицей:

1. **Контент читаем в состоянии по умолчанию, всегда.** Анимация только
   меняет то, что уже видно. Никаких `opacity: 0` в базовом состоянии.
2. Всё новое живёт внутри `@supports (animation-timeline: view())`.
3. Нет поддержки → страница ровно такая, как сейчас. Она уже работает.
4. `prefers-reduced-motion` — на каждом приёме, без исключений.

Каркас правила:

```css
@supports (animation-timeline: view()) {
  @media (prefers-reduced-motion: no-preference) {
    .selector {
      animation: name linear both;
      animation-timeline: view();
      animation-range: entry 40% cover 55%;
    }
  }
}
```

## 3. Распределение по секциям

Правило владельца — «через одну секцию» — берётся как жёсткое:
**один приём на секцию, соседние секции не повторяются, часть секций
намеренно неподвижна.**

| Секция           | Приём                                                             | Почему                                                    |
| ---------------- | ----------------------------------------------------------------- | --------------------------------------------------------- |
| **Hero**         | Параллакс-уход: контент отстаёт и растворяется при прокрутке вниз | Связывает первый экран со вторым. Скрамбл не трогается    |
| **About**        | Подсветка ключевых фраз растёт **по скроллу** вместо hover        | Приём уже нарисован — чинится только триггер              |
| **Showcasing**   | **Ничего не добавлять**                                           | Карусель движется сама, полоса прогресса на месте         |
| **Services**     | **Ничего не добавлять**                                           | Отклик на иконке уже есть                                 |
| **Advantages**   | Разноскоростной подъём: 7 карточек с разным смещением от скролла  | Единственное место, где список честно читается как список |
| **Testimonials** | **Ничего не добавлять**                                           | Автопрокрутка + прогресс                                  |
| **FAQ**          | **Ничего не добавлять**                                           | Аккордеон и есть движение                                 |
| **Contact**      | **Ничего не добавлять**                                           | Состояния формы и есть движение                           |

Ритм: громко → тихо-живое → самодвижущееся → покой → живое →
самодвижущееся → покой → покой.

## 4. Шаги реализации

Каждый шаг самостоятелен и заканчивается коммитом. Можно остановиться
после любого.

### Шаг 1 — About: подсветка ключевых фраз по скроллу

**Файл:** `src/components/aboutStory/style.css`

Сейчас `.about-story__mark` имеет `background-size: 100% 0.32em` в покое
и растёт до `100% 92%` по `.about-story__para:hover`. То есть **на
телефоне приём не срабатывает никогда**, а при обычном чтении со скроллом
его не видит вообще никто.

Сделать: та же геометрия и те же цвета, но `background-size` растёт по
мере прохождения абзаца через экран. Hover-версию оставить для мыши.

Самое заметное движение на строку кода — начинать отсюда.

### Шаг 2 — Hero: параллакс-уход

**Файл:** `src/sections/hero/style.css`

`.hero__inner` отстаёт от скролла и растворяется на `animation-range:
exit`. Верх страницы перестаёт быть отдельной картинкой и начинает
перетекать в следующую секцию.

Осторожно: у `.hero` уже есть класс `.hero--offscreen`, который ставит
`Hero.jsx` по `useInView` для остановки бесконечных циклов. Не
конфликтовать с ним.

### Шаг 3 — Advantages: разноскоростной подъём

**Файл:** `src/sections/advantages/style.css`

7 карточек приходят не по таймеру с задержкой (так было и так не надо),
а с разным смещением, привязанным к прокрутке. Смещение задаётся через
`:nth-child()` или CSS-переменную на элементе.

### Шаг 4 — Цифры About как показания консоли

**Файлы:** `src/sections/about/About.jsx` + новый хук

`4+ / 10+ / Middle / B2` (`ABOUT_STATS` в `src/const/index.jsx`)
набираются, когда блок проходит через экран.

Единственный шаг, который дороже остальных: чисто CSS-решения здесь нет,
нужен JS. Зато он привязывает вторую точку к «консольной» идентичности
проекта (DESIGN.md → Signature: The Developer's Console), и скрамбл
перестаёт быть одиноким приёмом.

Внимание: `Middle` и `B2` — не числа. Приём должен работать и с ними
(например, посимвольное проявление), иначе половина плашек выпадет.

### Шаг 5 — опция: акцентное слово в заголовках секций

**Файл:** `src/components/heading/style.css`

Единый приём на `.heading-sec__accent` во всех секциях.

Это **сознательное нарушение** правила чередования из §3. Обоснование:
акцентное слово — уже системный элемент по DESIGN.md («one accent word
per heading»), поэтому один приём на всех уместен. Но решение за
владельцем — не делать молча.

## 5. Отдельная опция с ценником

**Липкая витрина.** Секция Showcasing закрепляется, проекты сменяют друг
друга по мере прокрутки, без автоплея. Флагманский приём верхнего
эшелона, самый сильный визуально.

**Цена:** заменяет Swiper в `components/carousel/Carousel.jsx` и
выбрасывает полосу прогресса (`CarouselProgress`), которая владельцу
понравилась. Самый объёмный кусок работы из всех.

Поэтому — отдельная опция, а не шаг 6.

## 6. Открытый вопрос вне анимации

`ShowcasingCard` (карусель на главной) **не содержит ни одной ссылки и не
кликабелен**. С главной страницы дойти до проекта нельзя вообще —
карточка показывает картинку и название, и всё.

Это дыра в продукте, а не в анимации, поэтому в план работ выше не
входит. Но решение стоит принять отдельно.
