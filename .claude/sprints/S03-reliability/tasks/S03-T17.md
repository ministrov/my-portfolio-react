# S03-T17 — Мёртвые ключи и классы: доказать и удалить

**Исполнитель:** Junior · **Оценка:** 1 SP · **Статус:** To do
**Зависит от:** T09, T13 · **Ветка:** `sprint/S03-reliability`

> Лид перепишет карточку пошагово на старте, с номерами строк на коммите старта.

## Цель

Аудит нашёл ключи словарей и CSS-классы, которые похожи на неиспользуемые. Нужно для каждого доказать, что
он мёртв, и только потом удалить. Часть находок аудита оказалась ложной: `token-number` и `token-comment`
надо проверить особенно внимательно, потому что соседние `token-*` используются в `AuthorPhoto.jsx`.

## Что сейчас

Кандидаты:

- ключи: `promo.promoSlogan`, `faqs.open`, `faqs.close`, `footer.description`, `footer.reachOutButton`;
- классы: `token-number`, `token-comment` (`authorPhoto/style.css`), `carousel-progress--on-dark`
  (`carouselProgress/style.css`), `testimonials__heading` (`testimonials/style.css`).

## Как проверить, что готово

- По каждому кандидату в заметках карточки: как искал и что нашёл. Учитывай имена, которые собираются в
  коде из частей: например, ``t(`contactForm.errors.${errorKey}`)``.
- Удалено только доказанное, из обеих локалей сразу; `ru.json` и `en.json` по-прежнему совпадают по ключам.
- В браузере: FAQ, подвал, отзывы, IDE-карточка — как раньше.
- `npm run lint`, `npm run test:run`, `npm run build` — без ошибок.

## Новое для тебя

Как доказать, что код не используется: поиск с учётом собранных имён, вместо удаления «на глаз».
