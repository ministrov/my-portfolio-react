# S03-T06 — Source maps только для `npm run analyze`

**Исполнитель:** Лид · **Оценка:** 1 SP · **Статус:** Done
**Зависит от:** T04 · **Ветка:** `sprint/S03-reliability`

## Контекст

`vite.config.js:21`: `sourcemap: true`, потому что карты нужны `npm run analyze`. Из-за этого 15 MB из
22 MB сборки пользователь загружает на сервер вручную, а исходники открыты:
`/assets/index-CDQHeGN8.js.map` отвечает 200.

## Что сделать

- Карты только при анализе: `npm run analyze` собирает с картами сам, `npm run build` — без них.
- Проверить, работает ли `analyze` на Windows: в скрипте шаблон в одинарных кавычках (`package.json:25`),
  при аудите запуск `source-map-explorer` не дал результата.
- В шаг финальной выкладки — удалить `.map` с сервера.

## Критерии приёмки

- [x] В `build/` после `npm run build` нет `.map`; размер сборки записан в журнал.
- [x] `npm run analyze` работает на машине пользователя.
- [ ] После финальной выкладки `.map` на сайте отвечает 404. _Только на боевом сайте — на демо._
- [x] Definition of Done: lint, test:run, build, `CHANGELOG.md`.

## Затрагиваемые файлы

- `vite.config.js`, `package.json`, `CHANGELOG.md`

## Заметки по ходу

- **До правки** `analyze` работал: отчёт по 15 бандлам строился и с одинарными, и с двойными кавычками.
  «Не дал результата» при аудите — скорее всего, пустой терминал: отчёт открывается в браузере.
  Двойные кавычки всё равно взяты: в cmd одинарные доходят до программы как часть шаблона, и работает
  это лишь потому, что `source-map-explorer` их терпит.
- **Отступление от карточки, одобрено пользователем:** `analyze` собирает с картами в отдельную
  `build-analyze/` (+ строка в `.gitignore`), а не в `build/`. Иначе после анализа в `build/` снова
  лежат карты, и при ручной выкладке они уходят на сервер.
- **Размер `build/`:** 21,60 MB, 93 файла (карты — 14,86 MB, 15 файлов) → 6,74 MB, 78 файлов, карт 0.
  `build-analyze/` — 21,60 MB, 15 карт, отчёт по 15 бандлам.
- В выводе `analyze` два вида строк — не ошибки: у `rolldown-runtime` (служебный файл сборщика) карты
  нет; «Unable to map … bytes» — доли процента.
- Пользователь запустил `npm run analyze` у себя — отчёт открылся в браузере (2026-11-04).
- `CLAUDE.md:19` и `README.md:313` описывают `analyze` по-старому — правит T18.

## Проверка на демо, после выкладки

1. При выкладке удалить на сервере все `*.map` в `public_html/assets/`: новая сборка их не содержит,
   но старые файлы сами не исчезнут.
2. `curl -s -o /dev/null -w '%{http_code}\n' https://antoshkindev.ru/assets/index-CDQHeGN8.js.map` → 404
   (этот адрес отвечал 200 при аудите). Любой другой `.map` из старой выкладки — тоже 404.
