## Цель

У кнопки «наверх» 14 настроек, а вызывается она один раз и без них: `<Up />` в `Layout.jsx:54`. Половина
файла — код для случаев, которых нет. Нужно убрать настройки, нужные значения оставить константами.
Кнопка работает и выглядит как раньше.

## Что сейчас

`Up` (`Up.jsx:302-340`) принимает 14 настроек со значениями по умолчанию и передаёт их все в `UpButton`
(`Up.jsx:62-251`). Раз `<Up />` вызывается без настроек, на деле всегда работают только значения по
умолчанию. Они делятся на два вида:

| Настройка                                   | По умолчанию        | Что с ней делать                                        |
| ------------------------------------------- | ------------------- | ------------------------------------------------------- |
| `threshold`                                 | `300`               | константа                                               |
| `iconSize`, `iconColor`                     | `20`, `'white'`     | константы                                               |
| `debounceDelay`                             | `100`               | константа                                               |
| `animationDuration`, `animationEase`        | `0.65`, `'easeOut'` | константа-объект, как `COMPACT_HIDDEN` рядом            |
| `smoothScroll`, `enableEscape`              | `true`              | всегда «да» — проверка «а вдруг нет» лишняя             |
| `icon`, `className`, `ariaLabel`, `onClick` | пусто               | «ничего» — код, который их обрабатывает, лишний         |
| `autoFocus`                                 | `false`             | всегда «нет» — эффект автофокуса никогда не срабатывает |
| `tabIndex`                                  | `0`                 | у `<button>` это и так по умолчанию — атрибут не нужен  |

## Почему не просто…

- **…оставить настройки «на будущее»?** Это YAGNI («тебе это не понадобится»): настройка, которую никто
  не передаёт, — код без пользователя. Его надо читать, поддерживать и тестировать, а пользы ноль. Если
  когда-нибудь понадобится, например, другая иконка, — добавить один проп тогда, под конкретную задачу,
  дешевле, чем тащить 14 сейчас.
- **…удалить только пропсы, а код вокруг оставить?** Тогда останутся проверки вроде `if (onClick …)` для
  переменных, которых больше нет, — линтер их найдёт, но цель как раз в том, чтобы убрать и сами
  «а вдруг».
- **…удалять смело, если что-то сломается?** Страховка — `Up.test.jsx`: 6 тестов проверяют поведение
  кнопки (когда появляется, когда прячется), а не настройки. Если после правки они зелёные **без единой
  правки теста** — поведение не изменилось.
- **…заодно убрать параметр `enableEscape` из хука `useKeyboardHandlers`?** Хук — другой файл и не входит
  в задачу. Ему просто передаётся `true`.
- **…трогать JSDoc над `Up` и `UpButton`?** Не нужно: его перепишу я после ревью.
