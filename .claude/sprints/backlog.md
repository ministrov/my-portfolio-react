## Вёрстка

- **`body { min-width: 320px }` даёт горизонтальную прокрутку на экране 320 px при классических
  скроллбарах.** Найдено на визуальной проверке T13 (2026-11-27): в Chromium при `clientWidth` 310
  `window.scrollTo(200, 0)` оставляет `scrollX = 10`; в браузере пользователя с накладными
  скроллбарами прокрутки нет. Правило живёт с 2025-06-30 (`b9d9bcc0`), к бургеру отношения не имеет.
  Кандидатное исправление — `min-width: min(320px, 100%)`: проверено инъекцией в живой странице —
  `scrollX` 0 на 320 / 375 / 300, `body` = `clientWidth`. Нужна регрессия 320–375 на всех страницах и
  решение, считается ли 320 шириной содержимого или вьюпорта (S04-T13).

## Производительность

- **Общие чанки не дают отложенному `Contact` уйти из первой отрисовки.** В S04-T16 `lazy()` снял с
  первого кадра саму секцию, но граф загрузки упал только на 4,84 kB: rolldown перенёс 36,4 kB общих
  с eager-кодом модулей (`useBodyScrollLock`, `Tag` и их CSS) в предзагрузку `index.html`. Кандидат:
  развести общие зависимости или задать границы чанков (`manualChunks` / `output.advancedChunks`) так,
  чтобы код секции уходил целиком; мерить тем же методом графа — входной скрипт + все `modulepreload`
  и `stylesheet` из `index.html` (S04-T16).
- **Витрина: `srcset` для cover-картинок.** Один файл `-mobile-cover.webp` на все DPR: у vam-voda
  578 × 771 при показе 324 × 432 и 57,2 KiB, у waterdel 580 × 773 при 45,8 KiB. Аудит «Improve image
  delivery» называет 71 KiB экономии, но считает DPR 1 — при DPR 1,75 файл для 324 px нужен 567 px,
  то есть впритык. Правка: варианты 1x/2x с общим `sizes` или отдельные файлы под DPR; проверить всю
  витрину, а не два файла (S04 демо, 27.11, мобильный Lighthouse).
- **Мелкий блокирующий CSS после отложенного `Contact`.** `Tag-*.css` и `useBodyScrollLock-*.css`
  по 1,2 KiB стали отдельными render-blocking файлами в `index.html` (по 300 мс на Slow 4G в
  симуляции), всего блокирующего CSS 11,7 KiB / 1 360 мс. Решать вместе с пунктом «Общие чанки не
  дают `Contact` уйти»: объединять мелкие стили в `index.css` или выносить из критического пути
  (S04-T16, S04 демо).
- **Критическая цепочка шрифтов — 190 KiB / 200 мс.** Пять woff2 за `index.css`: Unbounded 50,02 +
  Oswald 36,64 + Unbounded 31,00 + Golos Text 37,34 + Oswald 35,18 KiB; «Maximum critical path
  latency: 200 ms». Preload Unbounded в T03 отклонён замером (ломал LCP EN) — смотреть подмножества
  и `unicode-range`, число начертаний и порядок `@font-face` (S04 демо, 27.11).
- **Главный поток на мобиле — 3,7 с.** Script Evaluation 1 177 мс, Other 1 130, Style & Layout 1 074,
  Rendering 331; 4 длинные задачи; мобильный Lighthouse-скор 77 против 99 на десктопе. Профилировать
  Performance-панелью: пересчёты лейаута и выполнение скриптов (S04 демо, 27.11).
- **63 анимации без композитинга.** «Avoid non-composited animations — 63 animated elements»: звёзды
  `AnimatedBackground` и появление секций анимируют свойства, идущие через paint/layout. Перевести на
  `transform`/`opacity`, уменьшить число звёзд на мобиле (S04 демо, 27.11).
