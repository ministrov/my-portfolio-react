## Что сделать

По ТЗ, блок 01, гайд, шаги 2, 3, 5, 6, 7:

- `StickyShowcase.jsx`: `isTouchLayout = useMediaQuery('(max-width: 1024px), (hover: none)')`;
  порядок веток: пусто → reduced motion → `isTouchLayout` → липкая витрина. В `useLayoutEffect`
  ранний выход по `isTouchLayout` — класс `sticky-showcase-pinned` не появляется на `<body>`;
  при смене ветки (поворот планшета) cleanup снимает его.
- `src/components/showcaseCarousel/ShowcaseCarousel.jsx`: разметка по паттерну карусели WAI-ARIA
  (region → трек → слайды `role="group"`), содержимое слайда, ссылка «Смотреть проект» без
  растягивания на карточку.
- Счётчик и точки: `IntersectionObserver` (`root` — трек, `threshold: 0.6`), клик по точке —
  `scrollTo` с учётом reduced motion; точки — `<button>` с подписью, `aria-current` у активной,
  счётчик `aria-hidden`.
- Ключи `showcasing.carouselLabel` и `showcasing.slideLabel` в `ru.json` и `en.json`.
- Мок `IntersectionObserver` в `src/setupTests.js` (нужен и этой задаче, и T08).
- Тест `ShowcaseCarousel.test.jsx`: 4 слайда, подписи, клик по точке → `scrollTo` с нужным `left`.
- `style.css` компонента — **только функциональный минимум** (трек: `position: relative`, flex,
  `overflow-x`, scroll-snap), чтобы проверить поведение; визуал — T05.

## Заметки по ходу

- **База для T05** (сборка до T04, `7e9ef333`): чанк `Showcasing` — JS 1,99 КБ gzip, CSS 1,65 КБ
  gzip. После T04 — JS 2,58, CSS 1,79 (+0,73 КБ); бюджет T05 «≤ 3 КБ» считать от базы.
- **Отступление: активный слайд — по `scrollLeft`, не по `IntersectionObserver`.** Со слайдом
  `min(520px, 72%)` на 860–1024 px соседний виден больше чем на 60% — «видимых» два; в конце ленты
  последний слайд не встаёт к началу, и «04 / 04» по IO не наступает. Ближайшая точка привязки с
  поправкой на максимальный скролл; клик по точке — та же формула
  `offsetLeft(слайд) − offsetLeft(первый)`, без жёсткого `− 16`. Мок IO в `setupTests.js` всё равно
  добавлен — для T08 и `whileInView`.
- **Баг в допущении ТЗ (риски блока 01):** cleanup эффекта не снимал класс при смене ветки —
  компонент не размонтируется, `isPinned` застывал в `true`. Класс теперь зависит от
  `isPinned && !isTouchLayout`; `StickyShowcase.test.jsx` это стережёт (проверено откатом фикса).
- **Сверх карточки:** ключи `showcasing.carouselRole` / `slideRole` — `aria-roledescription`
  локализован; ссылка названа через `aria-labelledby` (текст + `<h3>`) вместо `aria-label` —
  WCAG 2.5.3. `showcasing.eyebrow` не использован: позицию озвучивает подпись слайда.
- **Известное ограничение:** на тач-экранах шире ~1070 px (iPad в альбомной) два последних слайда
  видны целиком и делят одну точку привязки — точки 3 и 4 ведут в одно место, активна 4. Снять
  можно в T05 отступом в конце трека; на ширинах проверки (360–1024) не проявляется.
- `useReducedMotion` из motion читает настройку один раз при монтировании — в тестах замокан.
- **Критерий «поворот 768 ↔ 1024» в буквальном виде недостижим:** обе ширины попадают в
  `(max-width: 1024px)`, на планшете без мыши `hover: none` держит ленту в обеих ориентациях. Ветка
  меняется только через 1024/1025 (ресайз десктопа, iPad с трекпадом 1024 ↔ 1366). Проверяется
  двумя пунктами: 768 ↔ 1024 — лента остаётся, класса нет; 1280 → 1024 в закреплённой витрине —
  лента, класс снят (проверено в Chromium). Прыжок прокрутки на этой границе ожидаем: высота
  секции меняется примерно на 3 000 px.
