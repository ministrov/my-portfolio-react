## Что хорошо

- Нативная `<button type="button">` с `aria-expanded` и `aria-controls="mobile-navigation-menu"`;
  подписи меняются вместе с состоянием, клик передаёт `onToggle(!isOpen)`.
- Мёртвый код удалён — ни закомментированного импорта, ни `<Hamburger>`.
- **Проверка лида** (превью производственных сборок: текущая и HEAD в отдельном worktree, Chromium
  из Playwright):
  - Высота хедера **81 px и до, и после** — на 320, 390 и 767; кнопка **48 × 48** до и после.
  - Было: `DIV role="button"`, `aria-controls` = `null`. Стало: `BUTTON`,
    `aria-controls="mobile-navigation-menu"`.
  - Полоски: 28 × 3, цвет `rgb(37, 99, 235)` = `--color-blue-700`, шаг 8 px. Открыто:
    `translateY(±8px) rotate(±45deg)` (матрицы 0,7071…), средняя `opacity: 0`; линии пересекаются
    ровно в центре средней полоски (40,5 = 40,5), bbox крестика 21,9 px = (28 + 3) / √2.
  - Клик: открывает (`aria-expanded="true"`, диалог в DOM), закрывает — через 900 мс диалога нет,
    `body.overflow` = `unset` (исчезает после exit-анимации 0,5 с).
  - Tab на 320 и 390: логотип → бургер; кольцо `:focus-visible` — 2 px solid `rgb(37, 99, 235)`,
    offset 2 px, радиус 8 px; на 320 кнопка 246–294, прокрутки вбок нет (`scrollWidth` 320).
  - Клавиатура: **Enter открывает, Escape закрывает и возвращает фокус на бургер, Space
    открывает** — библиотека пробел не умела, ради этого задача и делалась.
- `npm run lint` — exit 0; `npm run test:run` — 30 файлов / **208 тестов**; `npm run build` — 430 мс.
- Тесты бургера и хедера переписаны лидом (часть плана): клик в двух состояниях, роль/тип/aria,
  открытие меню кликом, закрытие по пункту с возвратом фокуса.
