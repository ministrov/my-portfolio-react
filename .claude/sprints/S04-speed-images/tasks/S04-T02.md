# S04-T02 — База S04: Lighthouse, база регрессии, LCP-элемент

**Исполнитель:** Лид · **Оценка:** 2 SP · **Статус:** To do
**Зависит от:** — · **Ветка:** `sprint/S04-speed-images`

## Контекст

Без базы спринта о скорости нельзя сказать «стало быстрее»: метрика Performance на этом сайте скачет
на 15 пунктов от прогона к прогону (база S02: 67–82). База снимается один раз, до правок, в тех же
условиях, что и в S03, и на неё ссылаются T03–T05.

## Что сделать

1. **Сборка и сервер:** `npm run build`, затем `vite preview` на `http://localhost:4173` (сервер
   запускать напрямую через `node`, прецедент S03-T10).
2. **Lighthouse mobile CLI 13.5.0** (`npx lighthouse@13.5.0`), настройки по умолчанию, slow 4G + CPU ×4,
   по **3 прогона** и медиана по каждой метрике:
   - `/` RU и EN — Performance, LCP, CLS, FCP, TBT;
   - `/about` RU и EN — то же;
   - `/projects` RU — то же.
3. **LCP-элемент** на `/` и `/about` (RU): чем Lighthouse называет LCP — текст, картинка, какой
   селектор; приложить выдержку из отчёта (JSON из `--output json`). Это вход для T05.
4. **База регрессии вёрстки:** высоты страниц `/` и `/projects` на ширинах 320, 375, 768, 1024, 1280,
   1440, RU и EN — 24 значения. Методика — как в S03-T01 (Playwright, Chrome, `scrollHeight`).
5. `baseline.md` в папке спринта: условия, таблицы, выводы. Скриншоты — только если понадобятся
   следующим задачам; на закрытии спринта они удаляются.

## Критерии приёмки

- [ ] `baseline.md` заполнен: условия (браузер, Lighthouse, сборка, коммит), все таблицы, выводы.
- [ ] Три прогона на страницу, разброс записан; медиана посчитана.
- [ ] LCP-элемент назван с селектором и типом, доказательство — выдержка из JSON.
- [ ] 24 высоты страниц записаны; повторный проход совпадает до пикселя.
- [ ] `npm run lint`, `npm run test:run`, `npm run build` — без ошибок.
