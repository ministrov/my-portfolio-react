## Контекст

Заказчик убирает `hamburger-react`: кнопка — обычный `<button>`, её открытое и закрытое состояние —
на CSS. Это первая из трёх задач: разметка и вид сейчас, анимация перехода (T14) — мидл,
удаление зависимости, клавиатура и тесты (T15) — лид.

Зачем: библиотека рендерит `<div role="button">`, пробел его не нажимает, `aria-controls`
теряется. Нативная кнопка даёт роль, фокус, Enter и пробел бесплатно.

## Почему не просто…

- **…оставить `<div role="button">`?** Пробел не нажимает, `aria-controls` теряется, Enter
  изображается руками — ровно то, от чего уходим.
- **…взять `<span tabIndex={0}>`?** Фокус есть, ролей и клавиш — нет: то же самодельное колесо.
- **…оставить цвет `#0058a7`?** Это кобальт старой палитры: в проекте такого нет, `--color-blue-700`
  = `#2563eb`, и весь хедер на нём. **Решение лида:** полоски — `var(--color-blue-700)`; маленькое
  видимое отличие подтверждаешь на проверке.
- **…сделать кнопку меньше 48 × 48?** Прежняя зона нажатия — 48 × 48; меньше 44 px — шаг назад по
  доступности.
- **…позвать `onToggle` прямо из клика?** В состояние попадёт событие — см. ловушку выше.

## Новое для тебя

Нативная кнопка против `div role="button"`: что браузер даёт бесплатно — роль, фокус, Enter и пробел.
И зачем состояние рисовать в CSS по `aria-expanded`, а не по отдельному классу: состояние уже есть в
разметке для скринридера, CSS читает то же самое.

## Подсказки

- **Состояние в CSS:** селектор по атрибуту — `[aria-expanded='true']`; полоски — потомки кнопки.
- **`:focus-visible` вместо `:focus`:** кольцо только при навигации с клавиатуры, не после клика.
- **DevTools:** в Elements поменяй `aria-expanded` вручную — сразу видно крестик.
- **Документация:** MDN «`<button>`» и «Attribute selectors».
