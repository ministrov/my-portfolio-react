# S04-T14 — Анимация Squash на CSS

**Исполнитель:** Мидл (`layout-engineer`) · **Оценка:** 2 SP · **Статус:** To do
**Зависит от:** T13 · **Ветка:** `sprint/S04-speed-images`

## Контекст

T13 заменяет библиотечный бургер нативным `<button>` с тремя полосками и мгновенным переходом в
крестик. Заказчик просил **ту же анимацию**, что была у `hamburger-react` (вариант Squash). Эта задача —
вернуть движение на CSS.

Эталон — боевой сайт: он до релиза S04 работает на библиотеке, туда и смотреть. Ниже — точные значения
из исходника `hamburger-react@2.5.2` при `size={28}` (лид прочитал, 2026-11-20):

| Параметр           | Значение                                                                                                            |
| ------------------ | ------------------------------------------------------------------------------------------------------------------- |
| Общая длительность | 0,4 с                                                                                                               |
| Шаг движения       | 0,2 с                                                                                                               |
| Easing             | `cubic-bezier(0, 0, 0, 1)` (значение библиотеки по умолчанию)                                                       |
| Контейнер          | 48 × 48 px                                                                                                          |
| Полоска            | 28 × 2 px, `left: 10px`, `top: 15 / 23 / 31 px`                                                                     |
| Верхняя, открытие  | группа едет `translateY(8px)` — 0,2 с, без задержки; полоска поворачивается `rotate(45deg)` — 0,2 с, задержка 0,2 с |
| Нижняя, открытие   | `translateY(-8px)`, затем `rotate(-45deg)` — те же задержки                                                         |
| Средняя            | `opacity: 0` — 0,2 с, без задержки                                                                                  |
| Закрытие           | обратный порядок: повороты сразу, съезд — с задержкой 0,2 с                                                         |

Смысл исходника: сначала полоски «сжимаются» к центру, потом превращаются в крест; при закрытии —
наоборот, крест сначала распрямляется, потом полоски разъезжаются.

## Что сделать

1. **CSS в `src/components/navMobile/style.css`** (блок `≤ 767 px`, рядом со стилями T13): переходы на
   полоски и их группы с тем же шагом, задержками и кривой. Разметку T13 не переделывать без
   необходимости: если для двухфазного движения не хватает одного элемента — вопрос лиду, а не новая
   структура молча.
2. **`prefers-reduced-motion: reduce`** — переходы без движения: состояние меняется сразу, как до T14
   (решение лида; прецедент — `project-card__toggle-icon`, S03).
3. **Сверка с эталоном:** экран ≤ 767 px, окно 390 × 844, запись экрана или кадры на 0 / 100 / 200 / 300 /
   400 мс — на боевом сайте и на сборке ветки. Геометрия в конце анимации совпадает; на 200 мс — полоски
   уже в центре, поворота ещё нет.
4. **Проверка в браузере:** 320, 390, 767 px; открытие и закрытие по клику; Tab и Enter; после
   `prefers-reduced-motion` — мгновенно.

## Критерии приёмки

- [ ] Длительность и задержки в CSS совпадают с таблицей; кривая — `cubic-bezier(0, 0, 0, 1)`.
- [ ] Кадры на 0/100/200/300/400 мс совпадают с боевым сайтом (расхождение — только субпиксельное).
- [ ] Крестик в конце — ровно X: линии 45° и −45°, пересечение в центре, как у эталона.
- [ ] При `prefers-reduced-motion: reduce` переходов нет.
- [ ] Геометрия кнопки и высота хедера не изменились (замер T13 повторяется).
- [ ] `npm run lint`, `npm run test:run`, `npm run build` — без ошибок.
