# S04-T09 — `.gitattributes`: `.htaccess` в LF

**Исполнитель:** Junior · **Оценка:** 1 SP · **Статус:** In progress

Факты и номера — на коммите `c2cbd246`, рабочее дерево чистое (2026-11-26). Карточка переписана
пошагово на старте.

## Цель

Файл `public/.htaccess` в рабочей копии Windows получает переводы строк CRLF, и именно он уезжает на
хостинг: Apache читает `.htaccess` как есть, а команда проверяла файл в репозитории с LF. Нужно
правило в репозитории, чтобы у всех — и у новых участников — файл был в LF.

## Что сейчас (проверено 2026-11-26)

- `git ls-files --eol public/.htaccess` → `i/lf  w/crlf  attr/` — в индексе LF, в рабочей копии CRLF.
- `wc -c public/.htaccess` → **1237**; с LF будет **1218** — по одному лишнему байту на каждую из
  19 строк.
- `wc -c build/.htaccess` → **1237** — артефакт сборки, то есть на хостинг уходит файл с CRLF.
- `.gitattributes` в репозитории нет; `git check-attr -a public/.htaccess` выводит пустое `attr/`.
- `git config core.autocrlf` → `true` — Git сам переводит текстовые файлы в CRLF, потому что правила
  нет. В рабочей копии таких файлов **349**.

## Почему не просто…

- **…сказать всем «поставьте `core.autocrlf=false`»?** Это настройка каждого компьютера: у нового
  участника её не будет, и ошибка вернётся. Правило в репозитории работает у всех одинаково.
- **…починить один файл руками?** Следующий `git pull` вернёт CRLF — Git не знает, что файлу нужен LF.
- **…поставить правило на все файлы (`* text=auto`)?** Оно переворошит 349 текстовых файлов рабочей
  копии. Нужно только `.htaccess`, который читает Apache.

## Что сделать

1. Создать `.gitattributes` в корне репозитория. Одна строка: шаблон пути `*.htaccess` и атрибуты
   `text eol=lf`. Комментарий по-русски сверху — почему правило нужно. Синтаксис:
   [gitattributes](https://git-scm.com/docs/gitattributes).
2. `git check-attr eol public/.htaccess` → `eol: lf`.
3. Обновить рабочую копию, не меняя содержимого: удалить файл (`Remove-Item public/.htaccess`) и
   восстановить из репозитория (`git restore public/.htaccess`).
   `git ls-files --eol public/.htaccess` → `i/lf  w/lf`, `wc -c` → **1218**.
4. `git diff --stat` — `.htaccess` в списке изменённых быть не должно; `git status --short` — только
   новый `.gitattributes`.
5. `npm run build`, затем `wc -c build/.htaccess` → **1218** — это и уедет на хостинг.
6. `npm run lint`, `npm run test:run` — без ошибок.

## Новое для тебя

Как Git принимает решение о переводах строк: `core.autocrlf` — локальная настройка Windows,
`.gitattributes` — правило в репозитории; правило сильнее настройки. Смотреть, где файл какой, —
`git ls-files --eol`: `i/` — индекс, `w/` — рабочая копия.
