# S04-T09 — `.gitattributes`: `.htaccess` в LF

**Исполнитель:** Junior · **Оценка:** 1 SP · **Статус:** To do
**Зависит от:** — · **Ветка:** `sprint/S04-speed-images`

Номера строк и команды — на момент плана (2026-11-20). Карточка будет переписана пошагово на старте.

## Цель

После `git pull` на Windows файл `public/.htaccess` приходит с переводами строк Windows (CRLF). На
хостинг уходит файл, которого команда не проверяла: на выкладке S03 он был 1237 байт вместо 1218.

## Что сейчас

- `git ls-files --eol public/.htaccess` → `i/lf  w/crlf  attr/` — в репозитории LF, в рабочей копии
  CRLF.
- `wc -c public/.htaccess` → **1237** (должно быть 1218).
- `git config core.autocrlf` → `true` — Git сам переводит файлы в CRLF, потому что правила нет.
- `.gitattributes` в репозитории нет: `git check-attr -a public/.htaccess` выводит пустое `attr/`.

## Почему не просто…

- **…сказать всем «поставьте `core.autocrlf=false`»?** Это настройка каждого компьютера: у нового
  участника её не будет, и ошибка вернётся. Правило в репозитории работает у всех одинаково.
- **…починить один файл руками?** Следующий `git pull` вернёт CRLF — Git не знает, что файлу нужен LF.
- **…поставить правило на все файлы?** На Windows перестанут работать обычные текстовые файлы в их
  текущем виде; правило нужно только `.htaccess`, который читает Apache.

## Что сделать (направление)

1. Создать `.gitattributes` в корне репозитория. Формат — строка на шаблон пути и набор атрибутов; для
   этого файла нужен атрибут `eol` со значением `lf`, плюс `text`, чтобы Git считал его текстом.
   Синтаксис — в документации: [gitattributes](https://git-scm.com/docs/gitattributes).
2. Проверить, что правило действует: `git check-attr eol public/.htaccess` должен показать `eol: lf`,
   а `git ls-files --eol public/.htaccess` — `w/lf`.
3. Обновить рабочую копию файла, чтобы он стал LF без правки содержимого: удалить файл и попросить Git
   восстановить его из репозитория — `wc -c` покажет 1218.
4. Убедиться, что содержимое не изменилось: `git status --short` — только новый `.gitattributes`.

## Критерии приёмки

- [ ] `git check-attr eol public/.htaccess` → `eol: lf`.
- [ ] `git ls-files --eol public/.htaccess` → `i/lf w/lf`.
- [ ] `public/.htaccess` — 1218 байт, содержимое без изменений.
- [ ] `git status --short` — только `.gitattributes` (и переиндексация `.htaccess`, если Git её покажет).
- [ ] `npm run lint`, `npm run test:run`, `npm run build` — без ошибок.

## Новое для тебя

Как Git принимает решение о переводах строк: `core.autocrlf` на Windows против правил в
`.gitattributes`. Одно правило в репозитории сильнее локальной настройки.

## Затрагиваемые файлы

- `.gitattributes` (новый)
- `public/.htaccess` (только переводы строк, содержимое то же)
