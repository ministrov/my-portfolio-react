# S04-T06 — Кадр карточки 4:3 / 4:5: CSS и разметка

**Исполнитель:** Мидл (`layout-engineer`) · **Оценка:** 5 SP · **Статус:** Review (ждёт визуальной приёмки)
**Зависит от:** T02 · **Ветка:** `sprint/S04-speed-images`

## Контекст

Карточки на `/projects` показывают скриншоты в разных пропорциях: высота кадра 370–536 px, потому что
рамка следует натуральной пропорции файла (0,48 у Mish — 1,78 у витринных). Пользователь выбрал 4:3 на
десктопе и 4:5 на телефоне (решение 2026-11-20). Это даёт одну высоту кадра у всех восьми карточек и
убирает обрезку Mish посередине блока.

Где сейчас рамка (`src/components/projectCard/style.css`):

| Где                         | Строки  | Что делает                                                         |
| --------------------------- | ------- | ------------------------------------------------------------------ |
| база `.project-card__image` | 25–31   | `overflow: hidden`, `flex: 1 1 50%`, `max-height: 536px`           |
| `≤ 1274`                    | 197–201 | `width: 100%`, `max-height: 43.75rem` (700 px)                     |
| `≤ 1024`                    | 223–225 | `max-height: 46rem` (736 px)                                       |
| `≤ 768`                     | 454–464 | `aspect-ratio: 4 / 5`, `object-fit: cover`, `object-position: top` |
| база `.project-card__img`   | 141–144 | `height: auto`                                                     |

Выше 768 px пропорция нигде не задана — отсюда разнобой.

## Что сделать

1. **Рамка одинаковая:**
   - база (≥ 769 px) — `aspect-ratio: 4 / 3`, `max-height` убрать;
   - `≤ 768 px` — `aspect-ratio: 4 / 5` остаётся, но теперь это единственное отличие от базы;
   - `max-height: 43.75rem` и `46rem` в блоках `≤ 1274` и `≤ 1024` удалить — потолки больше не нужны;
   - `overflow: hidden` в базе остаётся: он и обрезка, и защита от растягивания скролл-контейнером.
2. **Картинка заполняет кадр:** `width: 100%`, `height: 100%`, `object-fit: cover`,
   `object-position: top` — с 769 px тоже, а не только на телефоне. Комментарий над правилом
   переписать под новую логику: пропорцию задаёт кадр, а не файл.
3. **Атрибуты `width`/`height`** в `ProjectCard.jsx` пока не трогать — их приводит к константе 4:3
   junior в T12. Проект нового файла в T07 делается после этой задачи.
4. **DESIGN.md** — лид обновляет раздел «Project card (/projects)» при ревью: 4:3 выше 768 px.
5. **Проверка:** ширины 320, 375, 768, 1024, 1280, 1440, RU и EN; высота кадра у всех 8 карточек равна
   (одна на ширину); карточка не ломается на 1269–1274 (полоса из бэклога — там карточка в одну
   колонку).

## Критерии приёмки

- [x] На 1280 и 1440 кадр 4:3: **520 × 390,5 px** у каждой карточки (±1 px). В карточке стояло
      «658 × 494» — это атрибут `width` у `<img>`, а не ширина кадра: колонка карточки 1136 − gap 48
      − padding 48 − border 2 = 520. Ошибка лида, исправлена по замеру; ревью — `reviews/S04-T06.md`.
- [x] На 375 и 768 кадр 4:5 (345 × 430,8 и 683 × 852,7), картинка прижата к верху
      (`object-position: 50% 0%`), пропорция не искажена.
- [x] На 320–1440 нет горизонтальной прокрутки: `scrollWidth − clientWidth` = 0 на всех ширинах.
      Кадр не выходит за колонку везде, кроме известных **2 px** на ≤ 1274 (`width: 100%` + border) —
      это задача T10 junior'а, T06 их не трогает и не увеличивает.
- [x] Потолков `536px`, `43.75rem`, `46rem` в файле нет: `grep` — 0 совпадений.
- [x] Нет нового CLS: измерено 0,001–0,002 на 1280/1440/1024, 0 на ≤ 768. Высота страницы меняется
      закономерно: на 1280 −22 px (кадр Mish вышел ниже), на 1024 −29, на 1269–1274 **+921**
      (одна колонка, кадр 1088 × 816,5 без потолка) — это прямое следствие решения, вопрос вынесен
      пользователю.
- [x] `npm run lint`, `npm run test:run`, `npm run build` — без ошибок. 30 файлов, 207 тестов.
