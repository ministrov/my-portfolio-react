- Каскад: база `21.75rem` (159–164) → ≤ 1274 `15.5rem` (214–216) → ≤ 1024 `100%` (317–319) →
  ≤ 768 `100%` (454–456) → **≤ 375 `55%`** (512–514) → ≤ 320 `100%` (519–521). Сужение живёт

- Номера строк в прежней версии карточки (524–526 / 530–533) были сняты до T10 и устарели.

## Почему не просто удалить строку

После удаления 55 % блок `@media (max-width: 320px)` (518–522) останется запросом, который ничего
не меняет, — читается как «на 320 нужно особое поведение». **Решение лида:** снять и 55 %, и
опустевший блок 320 — но только после замера, который покажет, что виновато именно ограничение.

## Что сделать — по шагам

0. **Пересказ в чат до кода** (2–3 предложения): что меняешь и по какому числу поймёшь, что готово.
1. **Замер «до».** `npm start`, `/projects`, DevTools → Device Toolbar. Ширины 320, 360, 375, 414.
   На карточке с тегами (Вам Вода) запиши ширину `.project-card__tools`, ширину
   `.project-card__skills` и число строк тегов. Ожидание по каскаду: 360 и 375 → 55 %, 320 и 414 →
   100 %.
2. **Правка.** Удали правило `.project-card__skills { max-width: 55% }` (512–514). Остальное в блоке
   ≤ 375 (кадр, заголовок, отступы) не трогай.
3. **Замер «после»** на тех же четырёх ширинах: ширина тегов = ширине `.project-card__tools`
   (±1 px), теги переносятся целиком. Если на 375 колонка всё ещё уже — ограничение пришло из
   другого правила, ищи последнее совпавшее в панели Styles.
4. **Опустевший блок 320.** Удали `@media (max-width: 320px)` с комментарием (518–522), повтори
   замер на 320: ничего не изменилось.
5. **Кадр на 320 и 375.** Запиши ширину и высоту `.project-card__image`: высота = ширина × 1,25
   ±1 px. Прокрутки вбок нет: в консоли `document.documentElement.scrollWidth` ≤
   `window.innerWidth`. Картинка прижата к верху, низ обрезан (`object-fit: cover`,
   `object-position: top`, 144–148).
6. **Регрессия.** Правка трогает только 321–375, поэтому 580, 768, 1024 меняться не должны. Реперы
   T10 по `/projects`: 768 → 11 524, 1024 → 10 198. На 580 сними замер до и после сам — репера нет.
   375 после правки, скорее всего, станет ниже 8 051 (T10) — это ожидаемо: теги займут меньше строк.
7. **Проверки.** `npm run lint`, `npm run test:run`, `npm run build` — без ошибок, вывод с цифрами
   в отчёт.

## Подсказки

- **Панель Styles:** на 375 правило `max-width: 55%` — активное, на 320 оно зачёркнуто: его
  перебивает `100%` из блока 320. Там же проверяется, что после правки последним стало `100%`.
- **Console:** ширина элемента — `getBoundingClientRect().width`; прокрутка —
  `document.documentElement.scrollWidth` против `window.innerWidth`.
- **Документация:** MDN «CSS каскад» (разделы Specificity, Order) и «max-width».
