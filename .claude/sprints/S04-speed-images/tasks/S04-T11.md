# S04-T11 — Карточка: теги на ≤ 375 и кадр 320–768

**Исполнитель:** Junior · **Оценка:** 1 SP · **Статус:** To do
**Зависит от:** T06, T07 · **Ветка:** `sprint/S04-speed-images`

## Контекст

Последняя точка из карточки S01-T09 — теги технологий в карточке проекта на самых узких экранах — плюс
проверка новой рамки 4:3 / 4:5 на телефонах после T06 и T07.

## Что сейчас (проверить замером на старте)

- `src/components/projectCard/style.css:524–526` — на ≤ 375 px у `.project-card__skills` стоит
  `max-width: 55%`. Теги переносятся (`flex-wrap: wrap` с ≤ 893 px), и на 375 px колонка тегов уже
  половины карточки: теги жмутся в узкий столбец вместо того, чтобы занять ширину.
- `src/components/projectCard/style.css:530–533` — на ≤ 320 px правило `max-width: 100%` это отменяет.
  То есть на 320 px всё нормально, на 375 — нет.
- После T06 кадр на ≤ 768 px — 4:5, после T07 файлы под него подрезаны; на 320–375 px проверить, что
  кадр не обрезает карточку и не даёт горизонтальной прокрутки.

## Что сделать (направление)

1. Замерить на 320, 360, 375 и 414 px ширину колонки тегов: сколько процентов карточки она занимает и
   сколько строк занимают теги. Решение о правке — по замеру, не по памяти: возможно, 55 % хватало
   старой разметке.
2. Привести к одному поведению с 320 px — либо тем же правилом, либо снятием ограничения.
3. Проверить кадр 4:5 на 320 и 375 px: пропорция, прижатие к верху, нет прокрутки вбок.
4. Пересказ в чат до кода — что меняешь и по какому признаку поймёшь, что готово.

## Критерии приёмки

- [ ] На 320, 360, 375 и 414 px теги занимают ширину карточки, переносятся по словам, никакой столбик
      не уже остальных.
- [ ] На тех же ширинах нет горизонтальной прокрутки; высота кадра = ширине × 5/4 (±1 px).
- [ ] Внешний вид на 580, 768, 1024 px не изменился (сверка с T06).
- [ ] `npm run lint`, `npm run test:run`, `npm run build` — без ошибок.
