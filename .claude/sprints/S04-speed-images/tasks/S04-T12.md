# S04-T12 — `imgHeight` → константа 4:3, чистка данных

**Исполнитель:** Junior · **Оценка:** 1 SP · **Статус:** In progress
**Зависит от:** T06 · **Ветка:** `sprint/S04-speed-images`

## Контекст

`imgHeight` появился в S01, когда кадр следовал натуральной пропорции файла: атрибуты `width` и
`height` резервировали место до загрузки. После T06 пропорцию задаёт кадр (`aspect-ratio`), картинка
заполняет его через `object-fit: cover` — а восемь разных значений в данных больше ничего не значат
и вводят в заблуждение.

## Что сейчас (проверено лидом на `46935556`, дерево чистое)

- `src/sections/projects/projects.js` — у 8 проектов `imgHeight` на строках 55, 78, 99, 122, 143,
  162, 182, 206: 470, 421, 472, 526, 494, 526, 526, 1383. Комментарий на строках 27–29 объясняет
  cover-файлы через `imgHeight` — после правки это упоминание станет ложью.
- `src/components/projectCard/ProjectCard.jsx` — JSDoc `@param {number} [props.imgHeight]` на 29,
  деструктуризация на 48, `<img width={658} height={imgHeight}>` на 112–117 (высота на 116).
- `src/components/projectCard/ProjectCard.test.jsx:46` — тест-фикстура передаёт `imgHeight={470}`;
  проверок на атрибуты в тестах нет. Эту строку тоже убираем — проп больше не существует.
- Других читателей нет: `ProjectsList` разворачивает проект целиком, больше `imgHeight` нигде нет.

## Почему не просто «оставить как есть»

Восемь значений обещают восемь пропорций, а кадр на экране один — 4:3 на десктопе и 4:5 на
телефоне. Это данные, которые не работают, и следующий человек потратит время, выясняя, почему
470 и 1383 дают на экране одно и то же.

## Что сделать — по шагам

0. **Пересказ в чат до кода** (2–3 предложения): что меняешь и по какому признаку поймёшь, что
   готово.
1. **Данные.** Удали `imgHeight: …` из всех 8 записей `projects.js`. Удобнее снизу вверх, чтобы
   номера строк не съезжали.
2. **Комментарий данных** (27–29): убери из него упоминание `imgHeight` — смысл остатка
   («cover-файлы нужны витрине, полные — карточкам») сохрани.
3. **Константы.** В `ProjectCard.jsx` над компонентом добавь две константы:
   `IMG_WIDTH = 658` и `IMG_HEIGHT = 494` (658 × 3/4 = 493,5, округляем до целого). Рядом — короткий
   комментарий на русском: атрибуты повторяют пропорцию кадра 4:3 и нужны только до загрузки CSS и
   картинки.
4. **Компонент.** Убери `imgHeight` из JSDoc (29) и из деструктуризации (48), а в `<img>` поставь
   `width={IMG_WIDTH}` и `height={IMG_HEIGHT}` (строки 115–116).
5. **Тест-фикстура.** Удали строку `imgHeight={470}` из `ProjectCard.test.jsx:46`. Сами тесты не
   трогай — убирается только мёртвый проп.
6. **Проверка в браузере.** `/projects` на 1280 и 375, DevTools → Network → «Disable cache» и
   «Slow 3G»; Rendering → «Layout Shift Regions». При загрузке карточки зоны сдвига не
   подсвечиваются, высота кадра до загрузки картинки равна высоте после.
7. **Проверки.** `npm run lint`, `npm run test:run`, `npm run build` — без ошибок, числа в отчёт.

## Новое для тебя

Зачем `<img>` атрибуты `width`/`height`, если размеры задаёт CSS: браузер узнаёт пропорцию до
загрузки файла и стилей. И как эта запасная пропорция соотносится с `aspect-ratio` кадра.

## Подсказки

- **Панель Elements:** выбери `<img>` и проверь атрибуты во вкладке Attributes; `Computed` покажет
  итоговую высоту кадра.
- **DevTools → Rendering:** «Layout Shift Regions» подсвечивает сдвиги синим при загрузке страницы.
- **Документация:** web.dev «Optimize CLS» (aspect ratio), MDN «aspect-ratio».
