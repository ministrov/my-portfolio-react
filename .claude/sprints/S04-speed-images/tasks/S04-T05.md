# S04-T05 — LCP: элемент и повторный замер

**Исполнитель:** Лид · **Оценка:** 2 SP · **Статус:** Done
**Зависит от:** T03, T04 · **Ветка:** `sprint/S04-speed-images`

## Контекст

LCP — узкое место с S01: 3,8 с на `/about` и 4,4 с на главной при норме 2,5 с. T02 назвал LCP-элемент
на базе, T03 убрал сдвиг шрифтов, T04 разгрузил главный чанк. Эта задача — проверить, сдвинулся ли LCP,
и точечно взяться за элемент, который его держит.

## Что сделать

1. Снять LCP после T03 и T04 в тех же условиях, что T02 (3 прогона, медиана), на `/` и `/about`, RU и EN.
2. Сравнить элемент LCP с базой T02. Возможные рычаги — по факту элемента:
   - текст → preload нужного начертания уже сделан в T03; проверить момент подмены шрифта;
   - изображение (герой, фото автора) → `fetchpriority="high"`, размеры под фактическую ширину,
     предзагрузка в `index.html` или из шапки страницы;
   - элемент ниже первого экрана → проверить, не вызван ли LCP смещением/ленивой загрузкой.
3. Повторный замер и запись цифр в журнал `plan.md`.

## Критерии приёмки

- [ ] LCP `/about` ≤ 3,0 с и `/` ≤ 3,5 с — медиана трёх прогонов; недостижение — цифры и причина
      в `CHANGELOG.md`. Медианы шести прогонов (Chrome 158): `/` RU **4,29 с**, `/` EN **4,21 с**,
      `/about` RU **3,87 с**, `/about` EN **3,63 с**. **Цели не достигнуты**, причина в
      `CHANGELOG.md`: в симуляции один TTFB — 3,54 с от LCP главной, а на `/about` LCP-элемент
      рисуется вместе с FCP, правка элемента там ничего не даёт.
- [x] Остальные метрики не хуже T02: CLS ≤ 0,1, FCP, TBT. CLS-медианы 0 на `/` и `/about` RU;
      на `/about` EN 0,075 — прежний шрифтовой сдвиг, он есть и в неизменённой сборке (см.
      `baseline.md`). FCP 3,66 / 3,59 / 3,42 / 3,18 с, TBT 135 / 78 / 265 / 233 мс — в пределах T04.
- [x] Правки LCP-элемента не меняют вид: визуальная проверка пользователем первого экрана `/` и `/about`.
      Заголовок `opacity: 1` в первом кадре во всех 12 комбинациях, высоты `/` совпали с базой S04
      до пикселя.
- [x] `npm run lint`, `npm run test:run`, `npm run build` — без ошибок. 30 файлов, 207 тестов.

## Заметки по ходу

- **LCP-элемент подтверждён по отчётам T04.** `/` — заголовок героя
  (`div.container > div.hero__inner > h1.hero__title > div`), `/about` — первый абзац
  `about-story`. На `/about` наблюдаемый LCP равен FCP (1 205 мс) — анимации на элементе нет.
- **Причина задержки на `/` измерена, а не угадана.** Playwright, мобильный контекст: обычный
  режим — FCP 316 мс, LCP 1 584 мс; `prefers-reduced-motion: reduce` (у заголовка остаётся только
  проявление из прозрачности) — FCP 280 мс, LCP 912 мс. Значит держит именно `opacity: 0`:
  невидимый элемент не считается крупнейшей отрисовкой, пока не станет видимым.
- **Правка:** из `titleReveal` убрана прозрачность, движение (`y`), доворот и блюр остались.
  Отдельный пресет `titleRevealReduced` удалён: без прозрачности `MotionConfig reducedMotion="user"`
  сам гасит `transform` и `filter`, и заголовок просто появляется. `ctaPop`/`ctaPopReduced` не тронуты.
- **Результат:** наблюдаемый LCP на `/` 288 мс = FCP (было 1 584); в симуляции задержка отрисовки
  элемента 1 686 → 852 мс; LCP медианой `/` RU 4,45 → 4,29 с, EN 4,31 → 4,21 с. FCP, CLS, TBT
  не хуже T04.
- **Почему цели карточки недостижимы правкой элемента:** на `/` в симуляции TTFB 3,54 с — это пол
  при любом элементе; на `/about` LCP = FCP (3,42 с RU), то есть узкое место — первый рендер
  (разбор и исполнение главного чанка), а не элемент. Остаточный рычаг — меньше кода до первого
  рендера; из найденного — секция `Contact` (108,5 kB / 38,08 gzip), вынесена в T16.
