# S05-T07 — «↑» под reduced motion, `typeof window`, `react/jsx-no-undef`

**Исполнитель:** Лид · **Оценка:** 3 SP · **Статус:** To do
**Зависит от:** T02 · **Ветка:** `sprint/S05-a11y-debt`

## Контекст

Три пункта бэклога: кнопка «↑» всегда вызывает `scrollTo` с `smooth`, игнорируя
`prefers-reduced-motion` (S03-T13, WCAG 2.3.3); 13 проверок `typeof window` в пяти прод-файлах —
серверного рендера в проекте нет (S03-T13); `react/jsx-no-undef` не включён, lint был чистым при
неимпортированном `UpButton` (S03-T13).

## Что сделать

1. `UpButton.jsx`: направление прокрутки — по `useReducedMotion` (проект уже использует его в
   `StickyShowcase`/`CtaButton`); при reduce — `'auto'`.
2. Убрать `typeof window` из `UpButton.jsx`, `ScrollToTop.jsx`, `hooks/useMediaQuery.jsx`,
   `hooks/useScrambleText.jsx`; в `AnimatedBackground.jsx` — **не трогать**: его строку снимает T11
   (мидл) вместе с декомпозицией. Проверить, что мёртвые ветки не прятали реальную логику.
3. `eslint.config.js`: включить `react/jsx-no-undef`, прогнать `npm run lint`, починить находки.
4. Тесты: защита от регрессии `typeof window` не нужна (jsdom и так без window-проверок); критерий —
   lint с новым правилом.

## Критерии приёмки

- [ ] При эмуляции `prefers-reduced-motion: reduce` кнопка «↑» скроллит мгновенно (проверка в
      браузере: `scrollTo` с `auto`), без reduce — плавно.
- [ ] `git grep "typeof window" src` — только `AnimatedBackground.jsx` (до T11) и `setupTests.js`.
- [ ] `react/jsx-no-undef` включён; `npm run lint` — exit 0.
- [ ] `npm run test:run`, `npm run build` — без ошибок.
