## Контекст

`src/components/stickyShowcase/StickyShowcase.jsx` — 333 строки: три ref на DOM, rAF-скролл,
непрерывный индекс (`--continuous-index`), состояние пина, отрезки сцены, обработчики навигации.
Самый тяжёлый компонент проекта и единственный, где правка требует понимать всё сразу.

## Что сделать

1. Вынести расчёт положения → индекса и отрезков в чистую функцию (вход — scroll, геометрия,
   количество; выход — индекс, прогресс) — тестируемую без DOM.
2. Вынести скролл-логику (слушатель, rAF, подписка на resize, reduced motion) в хук
   `useStickyShowcase`; компонент — разметка и вызов хука.
3. Тесты: на чистую функцию (границы, переходы между отрезками) и, если возможно, на хук с jsdom +
   моками rAF; проверить, что тесты умеют падать.
4. Поведение не меняется — доказательства: позиции `activeIndex` по скроллу до/после совпадают на
   1280 и 390 (замер лида на ревью), кадры сцены совпадают; визуальная приёмка пользователя.

## Критерии приёмки

- [ ] Логика позиции — чистая функция с тестами; скролл — в хуке; компонент заметно короче.
- [ ] Тесты умеют падать (сломать границу отрезка → красный).
- [ ] `activeIndex` по скроллу совпадает с прежней версией (числа в отчёте); кадры совпадают.
- [ ] Видимое поведение: пин, непрерывный заголовок, точки/стрелки, reduced motion — как было.
- [ ] `npm run lint`, `npm run test:run`, `npm run build` — без ошибок.
