# S05-T08 — i18next без `ToggleLang`, глифы `useScrambleText`

**Исполнитель:** Лид · **Оценка:** 3 SP · **Статус:** To do
**Зависит от:** T02 · **Ветка:** `sprint/S05-a11y-debt`

## Контекст

Два связанных долга (S03-T11, S03-T12): мост к i18next живёт в `hooks/useLanguage`, который
вызывается только из `ToggleLang` — переключение языка из другого места до i18next не дойдёт.
После смены языка подзаголовок героя ~0,55 с показывает глифы прежнего языка (`useScrambleText`);
в браузере не проверено.

## Что сделать

1. Проверить в браузере текущее поведение scramble при RU ↔ EN (записать «до»: кадры/время).
2. Мост: переключение i18n не должно зависеть от того, смонтирован ли `ToggleLang`. Решение по
   архитектуре — за лидом; не ломать правило «только компоненты в `.jsx`, хуки и контекст рядом»
   (`react-refresh`). Идея для обсуждения: `changeLanguage` в `LanguageProvider` (он монтируется всегда)
   с сохранением `useLanguage` как тонкого читателя.
3. Scramble: при смене языка перезапускать текст с новым языком, а не анимировать старые глифы —
   проверить `useScrambleText` и `HeroSubtitle`.
4. Тесты: добавить к мосту (jsdom), у `LanguageProvider`/`useLanguage` тесты есть — расширить;
   проверку анимации jsdom не тянет — браузерная проверка.

## Критерии приёмки

- [ ] Переключение языка работает и без `ToggleLang` в дереве (проверка тестом на провайдере).
- [ ] После смены языка подзаголовок героя не показывает глифы прежнего языка (кадры в браузере).
- [ ] `npm run lint`, `npm run test:run`, `npm run build` — без ошибок.
