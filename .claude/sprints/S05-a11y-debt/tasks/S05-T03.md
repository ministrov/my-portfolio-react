# S05-T03 — Меню: фокус после «Контактов» и после автозакрытия

**Исполнитель:** Junior · **Оценка:** 2 SP · **Статус:** To do
**Зависит от:** T02 · **Ветка:** `sprint/S05-a11y-debt`

## Контекст

Два пункта бэклога про фокус в мобильном меню (S01-T06, S01-T08): после пункта «Контакты» фокус
возвращается на бургер, а не ведёт к секции, куда пользователь перешёл; после автозакрытия меню
(раскладка перестала быть мобильной) фокус уходит на `body`, потому что бургер скрыт на ≥ 768 px.
Аудит T02 подтверждает или снимает оба пункта — работать по его вердиктам.

## Что сделать (направление)

1. Перечитать `MobileMenu.jsx` (возврат фокуса `lastFocusedRef`), `MenuItem.jsx`,
   `hooks/useGoToContacts.jsx` и `useMenuControl`. Понять, кто и когда возвращает фокус.
2. **«Контакты»:** после перехода к секции фокус должен оказаться на заголовке контактов (он с
   `id="contact-heading"`, скролл уже есть) — добавь `tabIndex="-1"` и фокус там, где это логично по
   архитектуре; не ломай возврат фокуса для остальных пунктов.
3. **Автозакрытие:** при закрытии из-за смены раскладки фокус не должен улетать в `body`; выбери
   осмысленную цель (например, первый элемент десктопной навигации) и обоснуй в отчёте.
4. Тесты — лид; ты проверяешь сценарии в браузере: меню открыто, Tab до «Контактов», Enter → фокус на
   заголовке; ресайз через 768 при открытом меню → фокус не на `body`.

## Критерии приёмки

- [ ] После Enter на «Контактах» фокус — на заголовке `#contact-heading`, прокрутка к секции.
- [ ] После автозакрытия меню (ресайз через 768) `document.activeElement` — не `body`; цель обоснована.
- [ ] Остальные пункты меню по-прежнему возвращают фокус на бургер.
- [ ] `npm run lint`, `npm run test:run`, `npm run build` — без ошибок.
- [ ] Проверка в браузере приложена к отчёту (что нажато, где фокус).
