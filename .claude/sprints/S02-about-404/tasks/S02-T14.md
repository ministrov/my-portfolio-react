# S02-T14 — Фолбэк на SPA: `public/.htaccess`

**Исполнитель:** Лид · **Оценка:** 2 SP · **Статус:** Blocked — нет доступа к хостингу
**Зависит от:** проверка `.htaccess` на сервере · **Ветка:** `sprint/S02-about-404`

## Контекст

Найдено в T01 (журнал `plan.md`, 2026-10-27). Хостинг — Timeweb: nginx перед Apache. На прямой
заход `/about`, `/projects` и любой неизвестный адрес Apache отвечает 404 своей страницей
«Not Found» (196 байт): фолбэка на `index.html` нет. Ломается цель спринта — рекрутер по прямой
ссылке на /about видит «Not Found», поисковик получает 404 на адреса из `sitemap.xml`; страницу
404 из T02 при прямом заходе никто не увидит.

## Что сделать

- `public/.htaccess` — Vite копирует `public/` в `build/` как есть:
  - существующий файл (ресурсы, `robots.txt`, `sitemap.xml`) отдаётся как есть;
  - маршруты приложения `/about`, `/projects` → `index.html` со статусом **200**;
  - любой другой адрес → `index.html` со статусом **404** (`ErrorDocument`) — сайт рисует
    `PageNotFound`, поисковик видит честный 404.
- Список маршрутов дублирует `src/App.jsx` — связь видна с обеих сторон: комментарий в
  `.htaccess` и в `App.jsx` рядом с `<Routes>`.
- Перед выкладкой — сверка с `.htaccess` на сервере, если он там есть: его правила (например,
  редирект на HTTPS) не затереть, а перенести.
- Выкладка — пользователь, через файловый менеджер Timeweb; скрытый файл `.htaccess` должен
  попасть в папку сайта.

## Критерии приёмки

Проверяются только на боевом сайте после выкладки, `curl -s -o NUL -w "%{http_code}"`:

- [ ] `/about`, `/about?lang=en`, `/projects` → 200, в ответе `index.html` сайта.
- [ ] `/no-such-page` → 404, в ответе `index.html` сайта; в браузере — `PageNotFound`.
- [ ] `/`, `/robots.txt`, `/sitemap.xml`, файл из `/assets/` → 200, как до правки.
- [ ] Правила серверного `.htaccess`, если он был, работают.
- [ ] Definition of Done: lint, test:run, build (`build/.htaccess` на месте), `CHANGELOG.md`.

## Затрагиваемые файлы
