Ловушки карточки проекта (`src/components/projectCard/`), S01-T09 (2026-10-22), S03-T14 (2026-11-10), S04-T06 (2026-11-25):

- **Пропорцию кадра задаёт CSS, а не файл (S04-T06).** `.project-card__image` — `aspect-ratio: 4 / 3` выше 768 px, `4 / 5` на ≤ 768; потолки 536 px / 700 px / 736 px убраны. `.project-card__img` заполняет кадр (`width/height: 100%`, `object-fit: cover`, `object-position: top`); атрибуты width/height у `<img>` — только резерв места, размер им больше не задаётся (раньше `height: auto` из S03-T14 компенсировал атрибут height).
- **На 1280/1440 кадр 520 px шириной, не 658.** Карточка 1136, padding 24, border 1, gap 48, flex 50/50 → контент кадра 518 × 388,5, рамка 520 × 390,5. **658 — это атрибут `width` у `<img>`** (и ширина кадра ровно на 769 px), в оценках его легко принять за отрисованную колонку. Проверяй ширину замером, а не атрибутом.
- **≤ 1274 карточка в одну колонку — 4:3 растягивается на всю ширину.** Замеры после T06: 1024 — 902 × 677 (было до 738); 1269–1274 — 1088 × 816,5 (было 702, страница +921 px); 769 — 659 × 495. Это следствие решения, а не регрессия; сравнивай с этими числами.
- **`.project-card__image` — content-box:** на ≤ 1274 `width: 100%` + border 1px даёт рамку на 2 px шире колонки (T10 junior). На десктопе рамка — flex-item, переполнения нет.
- **320 px + классический скроллбар:** `body { min-width: 320px }` при clientWidth 310 — документ скроллится вбок на 10 px (`overflow-x: clip` полосы не даёт, но `scrollLeft` доходит до 10). Не от T06.
- **CLS на /projects (десктоп) не нулевой и без картинок:** одна запись 0,003–0,005 около 520 мс, источник — текстовые узлы в `.header__actions`; вероятно, подмена шрифта в шапке (не доказано). Сравнивай с ней, а не с нулём.
- **Резерв места проверяй задержкой запросов, а не обрывом.** `page.route('**/*.webp')` копит маршруты, прокрутка вызывает все 8 ленивых запросов, потом `continue()`. `abort()` делает картинку битой, и Chrome рисует alt-текст вместо бокса загрузки. `networkidle` при задержанных запросах не наступит — бери `domcontentloaded`.
- **Фон под карточкой не белый вверху окна.** `body::before` — фиксированное кобальтовое пятно у верхних углов. Graphite (#6e6e6e) на белом даёт 5,1:1. В полосе ~90–190 px от верха окна на 390 (сразу под хедером, слева) — 3,9–4,4:1. Контраст светлого текста меряй по реальному фону вверху экрана, а не по белому.
- **`ProjectsList` проявляет карточки по очереди, `staggerChildren: 0.5`.** Пятая становится видимой только через ~2,6 с после загрузки. Снимок раньше — пустой фон. Жди `opacity === '1'` у `li`.
- **У Ratingus нет tablet/mobile-файлов (`srcSet=""`).** Браузер пропускает такой `<source>` и берёт десктопную `img` 1200×900. Остальные на ≤ 768 берут tablet-файл, на ≤ 375 — mobile (`BREAKPOINTS`).

**Why:** ничего из этого не видно при чтении CSS; проявляется только в замерах на конкретных ширинах, а ширина кадра расходится с атрибутом картинки.
**How to apply:** правишь кадр или картинку — меряй отрисованную рамку всех 8 карточек на 769/1024/1268/1274/1280 и ≤ 768, высоту текста против рамки, срез снизу и `scrollWidth`. Связано: [[project-desktop-unchanged-s01]], [[project-touch-verification]].
